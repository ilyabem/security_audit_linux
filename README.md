#  Linux Security Audit Multitool

Интерактивный аудит безопасности Linux-серверов на чистом Bash. Один файл, ноль
зависимостей за пределами базовой системы, вывод в терминал и в текстовый отчёт.

Кроме аудита умеет **применять исправления** — но не «слепым sed'ом»: для
критичных категорий (парольная политика/PAM, SSH, firewall) работает движок с
бэкапом, валидацией конфига и предохранителем, который откатит изменения, если
вы не подтвердите из нового сеанса, что вход в систему всё ещё работает.


## Возможности

**19 разделов проверок**

| | |
|---|---|
| Парольная политика (`/etc/login.defs`) | Сложность пароля (PAM / pwquality) |
| Учётные записи и shell | Конфигурация SSH |
| Криптография SSH (Ciphers/MACs/Kex/HostKey) | Таймаут бездействия shell (`TMOUT`) |
| Брандмауэр (ufw / firewalld / iptables) | Обновления системы |
| Сервисы и открытые порты | Файловая система и права доступа |
| Параметры ядра (sysctl) | Аудит и логирование (auditd, rsyslog, journald) |
| SELinux / AppArmor | Шифрование дисков (LUKS/dm-crypt) |
| Cron и планировщик | Сетевая конфигурация |
| NTP — синхронизация времени | DNS — конфигурация и безопасность |
|  Поиск бэкдоров и закладок | |

**Модуль поиска бэкдоров** (14 проверок): нестандартные SUID/SGID, исполняемые
и скрытые файлы в `/tmp` и `/dev/shm`, процессы с удалённым исполняемым файлом,
чужие cron-задачи, подозрительные `ExecStart` в systemd-юнитах,
`authorized_keys` с `command=`, нестандартные LISTEN-порты, инструменты
пентеста, подмены в `/etc/hosts`, опасные команды в `.bash_history`,
`/etc/ld.so.preload`, PAM-модули вне пакетного менеджера, недавно изменённые
критичные файлы, интеграция с `chkrootkit` / `rkhunter`.

**Интерактивная настройка порогов.** Минимальная длина пароля, сроки старения,
глубина истории, таймауты SSH и shell, число попыток аутентификации — всё
спрашивается перед запуском, причём в качестве значений по умолчанию
подставляются **текущие настройки системы**, а не абстрактные константы.

**Отчёт** пишется в `/tmp/security_audit_<host>_<дата>.txt` с правами `600`
(в нём имена пользователей, открытые порты и пути), без ANSI-мусора.

## Использование

### Интерактивный режим

```bash
sudo ./security_audit.sh
```

Сначала — настройка порогов, потом меню. Параметры вводятся один раз, меню
можно гонять сколько угодно (`s` — перенастроить, `q` — выход):

```
  1) Полный аудит (все разделы)
  2) Парольная политика + PAM
  3) SSH — конфигурация и криптография
  4) Учётные записи и права
  5) Сеть и брандмауэр
  6) Ядро, файловая система, шифрование
  7) Логирование, SELinux/AppArmor
  8) Поиск бэкдоров и закладок (отдельный модуль, долго)
  9) NTP — синхронизация времени
 10) DNS — конфигурация и безопасность
```

### One-shot режим

```bash
sudo ./security_audit.sh --full --report-only     # полный аудит, ничего не менять
sudo ./security_audit.sh --ssh                    # только SSH, с предложением фиксов
sudo ./security_audit.sh --backdoors --report-only
```

| Опция | Что делает |
|---|---|
| `--full`, `-f` | Полный аудит (все разделы) |
| `--password`, `--pam` | Только парольная политика и PAM |
| `--ssh` | Только SSH: конфигурация и криптография |
| `--accounts` | Только учётные записи и права |
| `--network` | Только сеть и брандмауэр |
| `--kernel` | Ядро, файловая система, шифрование |
| `--logging` | Логирование, SELinux/AppArmor |
| `--ntp` | Синхронизация времени |
| `--dns` | Конфигурация и безопасность DNS |
| `--backdoors` | Поиск бэкдоров и закладок |
| `--no-interactive` | Не спрашивать пороги, взять значения по умолчанию |
| `--report-only` | **Только отчёт**, не предлагать исправлений |
| `--timeout N` | Секунд на подтверждение перед авто-откатом (по умолчанию 180) |
| `--no-rollback-guard` | Отключить авто-откат по таймауту  не для прода |
| `--help`, `-h` | Справка |

Без root часть проверок недоступна (`/etc/shadow`, `sshd -T`, правила iptables) —
скрипт предупредит и продолжит с тем, что может прочитать.

## Как применяются исправления

Найденные проблемы разводятся по трём сценариям — в зависимости от того,
насколько больно будет, если фикс окажется неудачным.

### `password` — парольная политика и PAM

Точечные правки не предлагаются вообще. Вместо них запускается цельный модуль
`apply_password_policy()`:

1. бэкап всех затрагиваемых файлов (`pwquality.conf`, `faillock.conf`,
   `pwhistory.conf`, `login.defs`, весь релевантный `/etc/pam.d/`);
2. изменения выполняются в подпроцессе с `set -e` — первая же упавшая команда
   останавливает применение, не оставляя PAM в наполовину настроенном состоянии;
3. структурная валидация стека (`pam_unix.so` на месте, файлы не пустые) плюс
   `pamtester`, если установлен;
4. при любой ошибке — немедленный откат из бэкапа.

Debian/Ubuntu/Astra и RHEL/CentOS/Rocky/Alma обрабатываются по-разному: на RHEL
через `authselect enable-feature`, на Debian — аккуратной вставкой
`pam_faillock` в `common-auth`. Если стек не в штатной идиоме (SSSD, LDAP, AD)
или модуля нет на диске — скрипт **не трогает** auth-стек и говорит об этом.

### `ssh` и `firewall`

Батч с бэкапом, для SSH — обязательная проверка `sshd -t` перед `reload`. Если
конфиг не проходит валидацию, изменения откатываются, `sshd` не перезагружается.

SSH-директивы пишутся через `ssh_set_param()`, которая учитывает, что на
Ubuntu 22.04+/Debian 12 значения приходят из `/etc/ssh/sshd_config.d/*.conf`:
конфликтующие строки в drop-in'ах комментируются, а директива вставляется
первой строкой основного файла — до `Include` и до любого `Match`.

### `simple` — всё остальное

Ядро, файловая система, логи, cron, NTP, DNS. Каждая правка показывается вместе
с командой и применяется по отдельному подтверждению:

```
┌─ Исправление ─────────────────────────────────────────────────
│ Установить net.ipv4.conf.all.accept_redirects=0 (ICMP-редиректы отклоняются)
│ Команда: sysctl -w 'net.ipv4.conf.all.accept_redirects=0' && sysctl_persist ...
└───────────────────────────────────────────────────────────────
  Применить? [y/N/q(выход)]:
```

sysctl-параметры пишутся в `/etc/sysctl.d/99-security-audit.conf` (идемпотентно),
конфликтующие строки в `/etc/sysctl.conf` нейтрализуются — иначе «исправление»
не пережило бы перезагрузку.

##  Предохранитель от самоблокировки

Главный страх при автоматизации hardening: скрипт закрутил гайки, разорвал вашу
единственную SSH-сессию, и сервер остался недоступен. Поэтому после применения
изменений категорий `password` / `ssh` / `firewall`:

```
============================ ВАЖНО ============================
Изменения (ssh) применены, но ЕЩЁ НЕ ЗАФИКСИРОВАНЫ.
  1) Откройте НОВОЕ SSH-подключение к серверу, не закрывая текущее.
  2) Убедитесь, что вход и sudo всё ещё работают.
  3) Вернитесь сюда и подтвердите.

У вас 180 сек. Иначе — автоматический откат из /root/security-toolkit-backup-...
=================================================================
Введите YES для фиксации:
```

Не ввели `YES` — всё откатывается из бэкапа. Закрыли терминал или нажали Ctrl-C —
откатывается тоже: фоновый сторож переживает выход из скрипта и пишет в
`/var/log/security_toolkit_autorollback.log`.

Отключается через `--no-rollback-guard`, но на проде так делать не надо.

## Требования

- **Bash 4.3+** (используются ассоциативные массивы и nameref)
- GNU coreutils, `grep` с поддержкой PCRE (`-P`), GNU `sed`
- `systemd` (для проверок сервисов, journald, timesyncd)
- root — для полного набора проверок и для применения исправлений

Протестировано на Debian/Ubuntu и RHEL-семействе. На Alpine/busybox работать не
будет: скрипт завязан на GNU-утилиты и `systemctl`.

Опционально, если установлены — используются: `chage`, `ss`, `dig`, `chronyc`,
`ntpq`, `timedatectl`, `auditctl`, `aa-status` / `getenforce`, `lsblk`,
`chkrootkit`, `rkhunter`, `pamtester`, `authselect`.

## Ограничения, о которых стоит знать

- Без root эффективная конфигурация SSH собирается разбором `sshd_config` +
  `Include`; блоки `Match` при этом не учитываются. Под root используется
  `sshd -T`, который разбирает их корректно. Источник всегда указан в выводе.
- Проверка валидации DNSSEC делает внешний запрос (`dnssec-failed.org`). Без
  интернета даст ложноположительный результат.
- Полный аудит выполняет обход всей файловой системы (`find / -xdev`) — на
  больших разделах это минуты.
- Аудит опирается на конфигурационные файлы, а не на живое поведение системы.
  Это дополнение к CIS Benchmark / Lynis, а не замена им.
